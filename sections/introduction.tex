\section{Introduction}

Large language models (LLMs), built primarily on the Transformer architecture, support a broad range of language understanding, generation, and reasoning tasks \cite{vaswani2017attention,brown2020language,zhao2023survey}. Their substantial computation and memory demands often require inference across multiple GPUs. Tensor parallelism partitions computations within model layers, whereas pipeline parallelism assigns groups of layers to different devices. These strategies introduce different communication operations and execution dependencies. Consequently, evaluating LLM inference reliability requires considering both the model and its distributed implementation.

Soft errors can corrupt weights, activations, or intermediate results and cause silent data corruption without triggering observable failures. Device scaling and reduced operating voltages motivate continued attention to these faults \cite{mukherjee2005soft,borkar2006designing,baumann2005radiation,frustaci2015sram}. In distributed LLM inference, their effects can propagate along two interacting dimensions. Across devices, model partitioning and communication determine where corrupted values are consumed: tensor-parallel collectives can distribute errors through cross-rank aggregation, while pipeline transfers can carry them into downstream stages. Across tokens, autoregressive dependencies allow corrupted states or outputs to influence subsequent decoding steps, and persistent weight corruption can repeatedly perturb computation. These paths can amplify the effects of a local fault, making downstream-task degradation dependent on the parallel strategy, injection location, and generation workload.

Existing neural-network fault-injection tools provide important foundations for reliability analysis \cite{reagen2018ares,mahmoud2020pytorchfi,huang2024mrfi,mahmoud2021optimizing,wan2024mulberry}. However, many model-level tools primarily target model parameters and operator outputs, with limited native support for the distributed execution details that govern fault exposure and propagation. Injecting into a model tensor alone does not establish which rank owns the affected data, where it lies in a pipeline, or how subsequent communication spreads the perturbation. Likewise, estimating compute-fault counts solely from output-tensor size overlooks differences in the computation required to produce those outputs. Communication buffers introduce an additional injection target that must be associated with the appropriate collective operation or pipeline transfer. These limitations make it difficult to compare how practical parallel implementations affect LLM reliability.

Such comparisons also require an affordable and consistent evaluation workflow. Autoregressive decoding repeatedly executes model layers, while statistical experiments span fault settings, tasks, quantization methods, and parallel configurations. CPU-assisted bit modification can add repeated host--device transfers and synchronization to this workload. Moreover, language understanding, reasoning, and generation require different input processing and scoring procedures. Efficient injection and reusable task evaluation are therefore necessary to examine distributed reliability across a meaningful range of conditions.

We present vLLM-FI, a runtime fault-injection and reliability-evaluation framework built on vLLM. The native vLLM runtime provides a common execution environment for distributed parallelism, quantization, and optimized inference \cite{kwon2023efficient}. Within this environment, vLLM-FI models memory, computation, and communication faults, estimates compute exposure from runtime multiply--accumulate workloads, and injects communication faults into software-visible buffers. Configuration-driven targeting resolves fault settings to the appropriate Workers, ranks, stages, and runtime tensors. GPU-resident bit-flip operators reduce injection overhead, and integration with \texttt{lm-evaluation-harness} connects fault-affected inference with standardized downstream-task evaluation.

Our experiments use this framework to examine how execution configurations affect reliability. Under native communication workloads at a bit error rate of $10^{-8}$, pipeline parallelism retains 4.64 percentage points more normalized task performance than tensor parallelism on average across the evaluated model--task pairs. In the tested four-device configurations, the compared tensor-parallel ranks exhibit similar degradation, while earlier pipeline stages are more sensitive to memory faults and later stages to compute faults. These findings motivate accounting for communication behavior and stage position when evaluating reliability and selecting protection targets. Calibration and runtime comparisons further establish agreement with MRFI under the tested settings and demonstrate lower experimental cost.

The main contributions of this paper are summarized as follows:

\begin{itemize}
    \item We develop fault-exposure-aware models for distributed LLM inference, covering memory, computation, and communication faults. Compute-fault counts reflect runtime multiply--accumulate workloads, while communication-fault counts reflect buffer sizes in tensor-parallel collectives and pipeline-stage transfers.

    \item We design a vLLM-native injection architecture that maps fault configurations to distributed execution locations and supports quantized inference. GPU-resident, in-place bit flips enable efficient experiments across these configurations.

    \item We integrate standardized LLM task evaluation with fault injection and characterize reliability across tasks, quantization methods, communication strategies, and device positions. The experiments reveal strategy- and stage-dependent vulnerability that model-only evaluation can overlook.
\end{itemize}
